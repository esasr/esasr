# ESASR 检索与评测设计优化 V2

日期：2026-08-21

## 优化目标

赛题以 F1 Score 为主指标。V1 在 Top-100 的召回率达到 0.5411，但 Precision 只有 0.0156，说明主要问题不是候选不足，而是最终输出混入过多低相关论文。V2 因此将“宽召回候选集”和“提交给用户的高精度结果集”分离：后台保留 Top-100 用于后续融合和精排，前台默认输出经过验证的 Top-1，并继续展示可展开候选。

## V2 检索链路

1. **冻结语料**：固定 ScholarGym 570,206 篇论文及其 SHA-256，消除在线 API 漂移与限流影响。
2. **时间约束**：检索时排除晚于查询截止日期的论文，防止未来信息泄漏。
3. **等权字段 BM25**：标题与摘要权重均设为 1。开发集消融发现 V1 的标题权重 5 会放大偶然标题词重合。
4. **候选与最终输出解耦**：保留 Top-100 候选用于 Recall、MAP、nDCG 和后续精排；最终推荐默认输出 Top-1，以控制噪声并优化比赛主指标 F1。
5. **零成本基线**：本阶段 API 调用、LLM 调用和 Token 消耗均为 0，可在限流情况下完整复现。

## 防止调参泄漏

200 条固定样本依据查询 ID 的 SHA-256 奇偶值确定性拆分为开发集与冻结验证集。字段权重和最终输出规模只在开发集选择，随后在 98 条冻结验证集上一次性复测。

| 冻结验证集 | F1@1 | 变化 |
|---|---:|---:|
| V1：标题权重 5 | 0.1980 | — |
| V2：标题/摘要等权 | **0.2310** | **+16.7%** |

配对 bootstrap 的 F1 增量为 +0.0330，95% 置信区间为 [0.0051, 0.0677]，区间不跨 0。

完整样本上的配对 F1 增量为 **+0.0603**，相对提升 **32.4%**；5,000 次配对 bootstrap 的 95% 置信区间为 **[0.0308, 0.0925]**。平均检索延时从 1,000.9 ms 增至 1,022.3 ms，增加约 2.1%，仍属于相同成本级别。

## 下一轮建议架构

V2 是可靠的纯词法基线，下一轮应保持相同冻结数据和预算，逐项加入并做消融：

1. **规则查询分解**：从原查询提取主题、方法、数据集和限定条件，生成最多 3 个不调用 LLM 的子查询。
2. **多路召回与 RRF**：分别执行原查询、主题方法查询和短语查询，以 RRF 合并，目标是提升 Top-100 Recall。
3. **本地相关性精排**：只对 Top-20 候选运行本地 Cross Encoder，避免将 570K 文档送入模型。
4. **自适应输出规模**：根据第一名与后续候选的分数间隔输出 1–5 篇，而不是全局固定 K；阈值仅在开发集确定。
5. **双目标报告**：主表报告最终结果 F1；附表报告候选 Recall、MAP、nDCG、P95 延时、Token 和 API 调用，以证明增益不是通过扩大预算获得。

所有后续方法必须与 V2 使用相同的 200 条查询、时间约束、随机种子、候选上限和 bootstrap 设置，并在冻结验证集确认后再写入正式文档。
