# ESASR ScholarGym Pilot 实验报告

日期：2026-08-21
性质：真实在线 API pilot，不是完整 ScholarGym 或竞赛最终成绩。

## 1. 实验设置

- 数据：ScholarGym 公开 Gold Set；固定随机种子 2026。
- 抽样：PASA_AutoScholar、PASA_RealScholar、LitSearch 各 3 条，共 9 条查询。
- 查询规划：每条查询只生成一次并冻结，所有配置复用相同规划；规划 Token 成本计入每个配置。
- 检索后端：OpenAlex 与 Semantic Scholar 实时 API。
- 截断点：K=5、10、20；主表使用 K=20。
- 置信区间：5,000 次 query-level bootstrap，95% CI。

配置：

- A：单规划查询、OpenAlex、无第二轮。
- C0：双数据源、首轮最多两个查询、无第二轮。
- C1：双数据源、固定执行规划中的第二轮。
- D：双数据源、仅在覆盖缺口存在时执行第二轮。

## 2. Pilot 结果

| 配置 | F1@20 | Recall@20 | Precision@20 | MAP | nDCG | 平均 API 任务 | 平均延时 | 失败查询 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| A | 0.0417 | 0.2778 | 0.0228 | 0.1944 | 0.2271 | 1.00 | 5.81 s | 0/9 |
| C0 | 0.0346 | 0.2778 | 0.0185 | 0.1889 | 0.2222 | 3.11 | 9.03 s | 0/9 |
| C1 | 0.0346 | 0.2778 | 0.0185 | 0.1944 | 0.2271 | 5.33 | 21.28 s | 1/9 |
| D | 0.0346 | 0.2778 | 0.0185 | 0.1889 | 0.2222 | 3.56 | 11.79 s | 0/9 |

C1 有一条查询在 6 次有界退避后仍收到 Semantic Scholar 429，因此标记为 **incomplete，不参与正式主结论**。A、C0、D 均为 9/9 完整运行。

## 3. 当前可得结论

1. 该小规模 pilot 中，多源与第二轮检索没有提高 Recall@20；所有完整配置 Recall 均为 0.2778。
2. A 的 F1 略高，原因不是召回更多，而是返回集合更小、Precision 略高。该差异的 bootstrap 区间包含 0，且样本仅 9 条，不能宣称 A 显著优于其他方案。
3. D 相比固定第二轮 C1，平均逻辑 API 任务减少约 33%，平均延时减少约 45%；但 C1 存在一条限流失败，该结果只能作为成本方向性证据。
4. 当前最大瓶颈是**选择与过滤**：系统通常输出 15–20 篇候选，Gold 命中数有限，导致 Precision 仅约 0.02。下一步应优先增加 Selector/阈值过滤和 Cross Encoder，而不是继续扩大召回调用量。
5. 在 C0 基础上，D 增加约 14% API 任务和约 31% 延时，但未观察到质量提升。覆盖补检逻辑需要在更大冻结语料实验中重新验证。

## 4. 限流情况下如何完成正式测评

质量和在线运行必须分成两套实验：

- **离线质量主实验**：下载 ScholarGym 静态论文库、Semantic Scholar 数据集或 OpenAlex snapshot，本地冻结候选语料，完成 F1/Recall/MAP/nDCG 和消融。该结果不受 429、索引漂移和网络波动影响。
- **在线效率与可靠性实验**：按数据源建立独立串行队列，Semantic Scholar 控制在 Key 限额以内；记录 429、5xx、传输失败、真实重试等待、API 任务和端到端延时。
- 每条查询原子落盘并支持断点续跑。成功查询不重跑；失败查询冷却后用 `--retry-failures --only-id ...` 原位替换。
- 任一配置存在未恢复失败时标记 incomplete，不参与主 F1 排名；可以单独报告成功率与失败率。
- 响应缓存/冻结 replay 用于算法消融时，必须把逻辑 API 任务和真实 HTTP 请求分开，不能把缓存命中冒充在线调用节省。

Semantic Scholar 官方公布认证 Key 的入门限额约为全端点 1 RPS，并建议大规模工作使用可下载数据集；OpenAlex 可通过 `/rate-limit` 检查剩余额度，并提供完整数据 snapshot。

## 5. 后续正式实验

1. 下载并建立 ScholarGym 570K 静态论文索引。
2. 在 Test-Fast 200 条上运行 A、C0、C1、D。
3. 加入 E：D + Cross Encoder；再加入带阈值 Selector 的 E2。
4. 报告 F1@5/10/20、Recall、MAP、nDCG、95% CI、失败率、Token、API 任务与 latency P95。
5. 只在完整配置与等预算条件下形成竞赛结论。
