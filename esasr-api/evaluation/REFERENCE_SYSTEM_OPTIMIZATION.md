# ESASR 参考系统机制融合优化

日期：2026-08-21

## 设计原则

PaSa、SPAR、Ai2 Paper Finder 与 PaperQA2 的论文或代码分别针对不同数据、索引和评测协议，其公开数字不能直接与 ESASR 当前的 ScholarGym 200 条分层开发实验横向比较。本轮只迁移可解释、可控制预算、可做消融的机制，不复制未经验证的性能结论。

## 机制映射

| 参考系统 | 可迁移机制 | ESASR 实现 |
|---|---|---|
| PaSa | Crawler 与 Selector 职责分离 | 多源/多轮召回负责扩大候选；本地 Cross Encoder 与阈值门控负责最终筛选；阈值无命中时至少保留第 1 名 |
| SPAR | RefChain 查询分解与查询演化 | 保留结构化子查询树；覆盖缺口生成第二轮查询；从首轮高排名论文提取重复新术语，生成结果驱动的演化查询 |
| Ai2 Paper Finder | 多索引、引文追踪、预算内迭代 | OpenAlex、Semantic Scholar 与引文图作为独立召回通道；从高排名种子扩展相关论文；引文调用与文本检索共享同一 API 上限 |
| PaperQA2 | 全文优先的证据化回答 | 为主题、方法、数据集和领域逐项选择证据片段；存在全文字段时优先全文，否则回退摘要；前端可展开查看证据来源与覆盖率 |

## 新检索流程

1. 查询规划只执行一次，并复用规划缓存。
2. 首轮最多执行两个子查询的多源召回。
3. RRF 去重融合并执行年份、Venue、排除词和开放获取约束。
4. 从最高排名候选选取至多一个种子，在共享预算内进行引文网络扩展。
5. 重新计算多维覆盖率；存在缺口时优先生成缺口查询，再使用首轮结果生成演化查询。
6. 对候选池执行本地 Cross Encoder 精排。
7. PaSa 风格 Selector 阈值门控最终论文；全部低于阈值时保底输出第 1 名。
8. 为每篇论文生成逐条件证据、证据来源和证据覆盖率，并结构化展示。

## 成本边界

- LLM 查询规划：每个新查询最多一次，缓存命中时为零次。
- 默认 API 总任务上限：8，文本搜索与引文扩展共同计数，不能因新增通道突破上限。
- 默认引文种子：1 篇，每个种子最多 5 条候选。
- Cross Encoder：只处理 Top-20，完全本地运行，不消耗 LLM Token。
- 证据提取：确定性句子匹配，不调用 LLM；全文缺失时明确标注为摘要证据。

## 当前实验证据

静态 ScholarGym 语料不包含引文边，无法在同一离线环境中测量引文扩展收益；这部分已通过预算、去重和数据结构测试，但不得写成已取得 F1 增益。可直接离线评测的 V3 等权 BM25 + Top-20 Cross Encoder 在 200 条固定样本上达到 F1@1=0.2649、MAP@100=0.3007、nDCG@100=0.3773，API 和 Token 均为 0。V3 相对 V2 的增益方向为正，但冻结验证集配对 bootstrap 区间跨 0，因此仍需扩大冻结样本。

## 后续正式消融

建议按照以下顺序运行，所有配置固定查询集、候选上限、API 上限和随机种子：

1. V2：等权 BM25，无 Cross Encoder。
2. V3：V2 + Cross Encoder。
3. V4-a：V3 + 查询演化，不启用引文扩展。
4. V4-b：V3 + 引文扩展，不启用查询演化。
5. V4-c：V3 + 查询演化 + 引文扩展。
6. V4-d：V4-c + Selector 阈值门控。

主表报告最终 Precision、Recall、F1；诊断表同时报告候选 Recall、GT discard rate、MAP、nDCG、API 调用、Token、平均延时、P95 和失败率。存在 429 或缺失预测的运行标记为 incomplete，不参与主排名。
